## 결정과 이유

- **「고객사별 학습」은 기계학습이 아니라 예시로 만드는 규칙**으로 했습니다. 학습할 도면이 지금 없고(공유 불가), 품번 한 글자 오류가 곧 잘못된 매핑이라 결과를 사람이 읽고 고칠 수 있어야 합니다. 진짜 AI 학습은 2단계 — 고객사별 정답 표시 도면 수십 장과 보안 확인이 먼저이며, 지금 쌓는 규칙과 판별 엑셀이 그때 정답 자료가 됩니다. 화면 카드에도 같은 말을 적었습니다.
- **마스터·대조표 어디에도 없는 고객사 품번은 노랑(매핑 없음)** 으로 두었습니다. 고객사 품번만으로는 사내에 없는 자재인지 매핑만 빠진 것인지 알 수 없습니다. 「품번 후보 규칙」에서 빨강(신규)으로 바꿀 수 있고 확인 부탁으로 남깁니다. 규칙이 없을 때(모양을 모를 때)는 전처럼 신규(빨강)입니다.
- **담당자 처리 뒤에도 고객사 품번은 노랑**(「매핑됨·확정」)입니다. 노랑의 뜻이 「고객사 품번 표기」라 처리 여부와 별개이기 때문입니다. 손볼 것은 「손볼 항목」 수(`isOpen`)로 따로 셉니다.
- 부품표 한 행에 두 품번이 다 있으면 제조사 품번으로 판별합니다(수강생 4번 답: 제조사 품번이면 초록).
- 표 칸은 서로 가까워 조각 잇기 간격을 글자 높이의 0.35 배로 좁혔습니다(`mergeTextItems(items, { maxGap })`). 도면의 풍선 번호가 표 아래에 붙어 행으로 읽히지 않도록, 영역을 주지 않으면 줄 간격이 갑자기 벌어지는 곳에서 표를 끝냅니다.

## 결정과 이유

- **「매핑 필요(노랑)」를 넓게 잡았습니다** — ①제조사 후보 여러 개 ②사내 코드 빈칸 ③다른 고객사 품번으로만 등록 ④비슷한 품번만 있음. 원문의 노랑은 「매핑 필요한 고객사 자재」라 ③이 가장 가깝지만, ①②④도 사람이 정해야 하는 것이라 초록·빨강으로 단정하지 않았습니다. 범위는 수강생 확인이 필요합니다(기획서 10장 4번).
- **도면에 제조사 품번이 바로 적혀 있으면 기존(초록)**으로 봤습니다. 사내 코드가 하나로 정해지기 때문입니다. 고객사 품번 매핑이 없으니 노랑으로 볼지는 확인 대상입니다(10장 5번). 고객사 필터는 고객사 품번 열에만 걸고 제조사 품번·사내 코드는 고객사와 무관하게 찾습니다.
- **스캔본 OCR 은 넣지 않았습니다.** 도면 글씨는 작고 기울어져 브라우저 OCR 오독이 많고, 품번 한 글자 오독은 곧 잘못된 매핑입니다. 사람이 위치를 누르고 품번은 사람·AI(반자동)가 넣는 방식으로 하고, O↔0 같은 헷갈리는 글자만 다른 품번은 「비슷한 품번」으로 잡아 보여 줍니다.
- **색만으로 구분하지 않습니다.** 초록 실선·노랑 점선·빨강 겹선+빗금·회색 점선에 「번호 + 기존/매핑 필요/신규」 라벨을 붙였습니다. 노랑 라벨은 흰 글자가 안 읽혀 진한 글자를 씁니다.
- **도면 라벨·표·엑셀이 같은 번호**를 쓰도록 번호를 쪽 → 위 → 왼쪽 순서로 매깁니다(`sortMarks`). 수강생이 말한 「위치와 데이터의 이중 번거로움」을 번호 하나로 잇기 위함입니다.
- **담당자 처리는 품번 단위로 기억**합니다(v0.1 과 같은 원칙). 같은 품번이 도면 여러 곳에 있어도 한 번만 고르면 됩니다.
- **엑셀 첫 시트의 앞 네 열은 원문 순서 그대로**(자재 종류 | 도면 표기 품번 | 매핑된 사내 자재 코드 | 신규 여부)이고, 신규 여부는 기존/매핑 필요/신규 세 값입니다. 좌표 단위는 PDF=pt(쪽 원래 크기, 왼쪽 위 기준), 이미지=px 이며 엑셀에 함께 적습니다.
- **도면 파일은 저장하지 않습니다.** localStorage 용량이 작고 고객사 기밀이라, 표시·처리만 저장하고 도면은 다시 올리게 했습니다(같은 이름이면 저장된 표시를 그대로 이어 씀). 예시 도면은 새로고침 뒤 자동으로 다시 그립니다.
- **file:// 에서도 PDF 가 열리게** — Worker 가 막히므로 `pdf.worker.min.js` 를 일반 스크립트로 먼저 읽어 메인 스레드에서 돌립니다(data09-01 과 같은 방식). 웹 주소에서는 Worker 로 돕니다.
- **글자를 윤곽선으로 바꾼 PDF·스캔 PDF** 는 추출이 0개가 되므로 자동으로 「위치 표시」로 바꾸고 안내합니다.

## 결정과 이유

- **열 이름을 코드에 박지 않고 열 연결 화면을 두었습니다.** 두 마스터 엑셀의 실제 열 구성을 아직 받지 못했기 때문입니다. 열 이름으로 짐작해 미리 골라 두고, 사람이 고친 연결은 열 이름 기준으로 저장해 같은 양식 파일에 다시 씁니다.
- **품번은 먼저 적힌 그대로 비교하고, 없을 때만 정리(공백·하이픈·대소문자)해서 비교합니다.** 정리해서 맞은 경우는 「표기 차이 매칭」으로 따로 표시합니다. 품번 한 글자 차이가 다른 자재일 수도 있어 담당자가 눈으로 볼 수 있게 하려는 것입니다. 점·밑줄·슬래시 무시는 기본으로 꺼 두었습니다.
- **도면 품번은 고객사 품번 → 제조사 품번 → 사내 코드 순서로 찾습니다.** 도면에 제조사 품번이 바로 적힌 경우도 찾기 위함입니다. App Spec 에서 나온 터미널·실 품번은 제조사 품번이라 제조사 열부터 찾습니다.
- **자동으로 정할 수 없는 것은 정하지 않습니다.** 후보가 여럿이면 확인 대상으로 두고 담당자가 고르거나 직접 입력합니다(기획서 2.2). 미확정 행도 BOM 에서 빼지 않고 「확인 필요」로 남겨, 조용히 빠지는 자재가 없게 했습니다. 내보내기 전에 미해결 건수를 경고합니다.
- **커넥터 품번이 확정되기 전에는 그 커넥터의 터미널·실을 산출하지 않습니다(산출 보류).** 후보 커넥터마다 적용 터미널이 다를 수 있기 때문입니다.
- **담당자 선택은 품번·위치 단위로 기억합니다.** 같은 실 품번이 여러 커넥터에 쓰여도 사내 코드 선택은 한 번만 하면 됩니다.
- **BOM 은 같은 사내 코드끼리 합치고, 근거 열에 위치별로 어느 App Spec 행·매핑 행에서 왔는지 남깁니다**(기획서 9장 「판단 근거 기록」).

## 가정

- 부품 LIST 의 회로 표는 「한 행 = 커넥터 한 극에 꽂히는 전선 한 가닥」으로 보고, 행마다 터미널 1개·실 1개로 셉니다(기획서 5장 「회로(사용 극) 수 기준」). 극 번호를 비워 두면 행 하나를 한 극으로 셉니다.
- Application Spec 은 「한 행 = 커넥터 하나와 전선 규격 범위 하나에 쓰는 터미널·실(·방수전)」로 보았습니다. 한 칸에 여러 품번이 있으면 나눠 읽고, 규격 범위 칸이 둘 다 비어 있으면 모든 규격에 적용되는 것으로 봅니다(불러올 때 안내).
- 실 칸이 비어 있으면 「실 없음」(비방수 커넥터)으로 봅니다. 한 규격에 실 있음·없음 행이 섞이면 후보가 둘인 것으로 보고 담당자가 고릅니다.
- 전선 규격은 같은 단위(sq, mm²)의 숫자로 비교합니다. AWG 표기는 단위 변환 기준을 확인하지 않아 읽지 않고 확인 대상으로 둡니다.
- 방수전은 빈 극 수 = 극수 − 회로 수로 계산하고, App Spec 에 방수전이 적힌 행이 없는 커넥터는 비방수로 보고 넣지 않습니다(설정에서 켤 때만).
- 전선 자체(길이 기준 자재)는 BOM 에 넣지 않았습니다. 길이 단위와 전선 품번 규칙이 제출 자료에 없습니다.
- 예시 데이터의 품번·코드·고객사는 모두 지어낸 것입니다.
